# Sample Stakeholder Notes

## Project
Customer Support Request Management Platform

## Current Situation
Customer support requests are currently received through email, phone calls, and spreadsheets. Because information is stored in multiple places, support agents cannot easily track request status or identify which requests require immediate attention.

## Business Need
The organization needs a centralized platform where support requests can be created, assigned, prioritized, tracked, and resolved.

## Stakeholders
- Customers
- Customer Support Agents
- Support Managers
- System Administrators
- Reporting Team

## Initial Requirements
- Customers should be able to submit support requests.
- Support agents should be able to view and update assigned requests.
- Managers should be able to assign requests to agents.
- Requests should have priority levels.
- Users should receive notifications when request status changes.
- Managers need dashboards showing open, pending, and resolved requests.
- The system should maintain an audit history.

## Open Concerns
- Priority definitions are not finalized.
- Notification channels need confirmation.
- Response-time targets are not yet approved.
- User roles and access permissions require clarification.
